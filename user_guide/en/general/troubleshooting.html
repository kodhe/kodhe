Troubleshooting

A collection of the error messages that appear most often during development, together
with their causes and solutions. All of them already have a fix in the framework — update
your repository first (git pull + composer dump-autoload).

1. Class "Kodhe\UserAgent\UserAgent" not found (or any other Kodhe\<X>\<Y>)

Cause: code/config uses the legacy namespace without the Framework prefix, which is
not registered in the autoload.
Solution: switch to the active FQCN — see the migration map.
Example: Kodhe\UserAgent\UserAgent → Kodhe\Framework\Agent\UserAgent.
The $CI->load->library('user_agent') loader has fixed its mapping since PR #194.

2. Unknown column 'data' in 'SELECT' (database sessions)

Cause: the session table does not use the modern CI3 schema.
Solution: create the table according to the session package README:

CREATE TABLE ci_sessions (
  id VARCHAR(128) NOT NULL,
  ip_address VARCHAR(45) NOT NULL,
  timestamp INT UNSIGNED DEFAULT 0 NOT NULL,
  data BLOB NOT NULL,
  PRIMARY KEY (id),
  KEY ci_sessions_timestamp (timestamp)
);

then set $config['sess_save_path'] = 'ci_sessions';. The driver now validates the
schema and gives a clear message when columns are missing (PR #192). The old legacy
lastactivity column is still supported for garbage collection.

3. Unable to inspect session table '' / strcspn(): Argument #1 ... null given

Cause: sess_save_path is empty/null while sess_driver = database.
Solution: fill in the table name in the config (see #2). The framework now fails fast
with an explicit message instead of a confusing TypeError (PR #192/#196). For quick
development, use 'sess_driver' => 'files', 'sess_save_path' => sys_get_temp_dir().

4. "Cannot resolve class ..." errors inside packages

Cause: usually the composer autoloader was not regenerated after switching
folders/branches, or a bootstrap helper file is not loaded.
Solution: run composer dump-autoload then composer test; the actual per-package
results are recorded in issues #148–#175.

5. index.html shadows the application

The repo/app root sometimes contains a default index.html; point the DocumentRoot at
the public/ folder or delete that file.
