Creating a New Project (php console new)

The new command in the Kodhe Console scaffolds a ready-to-run Kodhe Framework
application skeleton: the standard folder structure (PascalCase, no _), a
composer.json with the PSR-4 App\ mapping, bootstrap files, configuration, an
.env template, plus starter code (controller/model/view/routes) so that
php console serve works immediately.

This document covers the new and serve commands, which form the standard pair for
starting a project locally.

1. Prerequisites

RequirementNotes
PHP>= 8.1
Composerto install dependencies after scaffolding
Kodhe Consoleavailable from the framework checkout (bin/console) or from the kodhe/framework package

You do not need an existing project — new creates the target directory from scratch.

2. Basic command

php console new my-app

Recognised aliases: new:project, create-project.

php console create-project my-app     # same as: php console new my-app

Options

OptionFunction
--forceScaffold into an existing, non-empty directory (generated files will overwrite files with the same name)
--minMinimal skeleton: folders + config only, without demo code (Home controller, Base model, welcome view). Instead, .gitkeep files are created in the empty folders

Examples:

php console new my-app --min          # clean skeleton, no demo
php console new . --force             # populate an existing current directory

If the target directory already contains files and --force is not given, the command
stops with an error message and exit code 1.

3. Generated structure

my-app/
├── app/
│   ├── Config/
│   │   ├── config.php            ← main configuration (routing, session, etc.)
│   │   ├── routes.php            ← CI3-style routes (legacy router)
│   │   └── routes_modern.php     ← modern router routes (Route:: facade)
│   ├── Controllers/
│   │   └── Home.php              ← App\Controllers\Home (skipped with --min)
│   ├── Models/
│   │   └── Base.php              ← example model (skipped with --min)
│   ├── Middleware/               ← (empty in demo mode)
│   ├── Libraries/
│   └── Views/
│       └── home/index.php        ← welcome view (skipped with --min)
├── bin/
├── database/
│   └── migrations/
├── public/
│   └── index.php                 ← front controller
├── storage/
│   ├── Cache/  Logs/  Session/  Uploads/
├── tests/
├── console                       ← project console entry point (chmod +x)
├── composer.json                 ← psr-4 "App\\": "app/", require kodhe/framework ^1.0
├── .env / .env.example           ← APP_*, DB_*, SESS_SAVE_PATH
├── .gitignore
└── readme.md

Important notes:

  • The project name in composer.json is derived from the folder name (lowercase, illegal characters → -), the prefix stays app/<name>.
  • The project's console looks for vendor/autoload.php at the project root (falling back one level up), so it works after composer install.
  • Folder conventions follow the Kodhe standard: PascalCase, no underscores (see folder-structure-and-routing).

4. Built-in configuration contents

.env

APP_NAME=Kodhe App
APP_ENV=development
APP_DEBUG=true
APP_URL=http://localhost:8080

DB_HOST=127.0.0.1
DB_USERNAME=root
DB_PASSWORD=
DB_DATABASE=kodhe_app
DB_DRIVER=mysql

SESS_SAVE_PATH=storage/Session

SESS_SAVE_PATH must point to a writable folder when using the file session
driver — the default value storage/Session is already provided.

app/Config/config.php

Contains safe defaults for development: an empty index_page (clean URLs), the modern
router active side by side with the legacy router, and cache_routes enabled only when
ENVIRONMENT === 'production'.

Routes

  • routes.php — CI3 style: $route['default_controller'] = 'Home/index'; served by the legacy router.
  • routes_modern.php — fluent style: Route::get('/', 'App\Controllers\Home@index'); The modern router is checked first when enable_modern_routing is active, so both files can coexist. Details: services-modules-routing.

Starter code

App\Controllers\Home extends BaseController with an index() method
(rendering view('home/index', ...)) and hello(string $name) — enough to verify that
routing, controllers, and views work before you write your own code. Component writing
standard: app-components.

5. Running the dev server (serve)

cd my-app
composer install          # install kodhe/framework + generate the autoloader
php console serve         # http://localhost:8080
OptionDefaultDescription
--host=localhostInterface/address binding (e.g. 0.0.0.0 to expose it on the network)
--port=8080TCP port; validated 1–65535, anything else errors

Under the hood serve runs the PHP built-in server with public/index.php as the
router script, so every request goes through the front controller. Example:

php console serve --host=0.0.0.0 --port=3000

A composer script is also available: composer serve.

6. Quick flow from zero to the first page

php console new my-shop && cd my-shop
composer install
php console serve
# open http://localhost:8080 → welcome page from App\Controllers\Home@index

Continue developing with the code generators:

php console make:controller Blog    # app/Controllers/Blog.php (namespace App\Controllers)
php console make:model Post         # app/Models/Post.php
php console make:migration create_posts_table
php console make:middleware Auth
php console make:crud Post title:string body:text   # a complete CRUD set (model+controller+migration+views)

Full list of scaffold commands: cli-console.
Step-by-step CRUD generator guide: generator-crud.

7. Notes & limitations

  • new does not run composer install automatically — dependencies are installed manually following the "Next steps" instructions printed by the command.
  • Generated files are silently overwritten when they already exist (especially with --force); commit/backup your target directory first.
  • To migrate an existing CI3 project (not a new project), do not use new; follow the migrating-from-ci3 procedure — new is useful for preparing a pure Kodhe skeleton as a migration destination.
