Security

This page covers the security features currently supported by Kodhe Framework: XSS filtering, CSRF protection, input filtering, password hashing, data encryption, secure cookies & sessions, rate limiting, and input validation. Each section includes notes on migrating from CodeIgniter 3 where relevant.

All APIs below have been verified against the package source code (framework/src/Support/Legacy/, http/src/, session/src/, encrypt/src/).

2. XSS Filtering

2.1 API

The compatibility kernel provides a class that is a direct port of CI_Security:

use Kodhe\Framework\Support\Legacy\Security;

$security = new Security();
$clean    = $security->xss_clean($untrustedHtml);          // plain string
$isImage  = $security->xss_clean($fileContent, true);      // image-check mode
$safe     = $security->sanitize_filename($name);           // safe file name
$decoded  = $security->entity_decode($str);                // decode HTML entities

Available methods: xss_clean(), sanitize_filename(), entity_decode(), strip_image_tags(), get_random_bytes(), xss_hash().

Global helpers (load with $this->load->helper('security')):

xss_clean($str, $is_image = false);
sanitize_filename($filename);
encode_php_tags($str);   // escape PHP tags so they cannot be evaluated
strip_image_tags($str);
do_hash($str, $type = 'sha256');  // deprecated — use native PHP hash() instead

2.2 Global XSS filtering (CI3 behaviour)

As in CI3, the legacy input applies per-request XSS cleaning through the second flag:

$name = $this->input->post('name', true);   // filtered through xss_clean()
$id   = $this->input->get('id', true);

Recommendation: do not rely on global filtering. Store raw data, then escape on output (htmlentities() / the view engine). xss_clean is a good fit for rich-text input that will actually be rendered.

2.3 Migration from CI3

CI3 patterns keep working as-is in the compatibility kernel:

// Old CI3 code — still works
$this->security->xss_clean($data);              // via $this->load->library('security')
$this->input->post('email', TRUE);

For new code, call the class directly (new Security(...)) or the global helpers — $this->load->library('security') is no longer needed.

3. CSRF Protection

3.1 Configuration (config.php — the CI3 format is accepted directly)

$config['csrf_protection']   = TRUE;
$config['csrf_token_name']   = 'csrf_test_name';
$config['csrf_cookie_name']  = 'csrf_cookie_name';
$config['csrf_expire']       = 7200;          // seconds
$config['csrf_regenerate']   = TRUE;          // new token on every submit
$config['csrf_exclude_uris'] = ['api/webhook/[A-Z0-9-_]+'];  // regex, without delimiters

3.2 How it works (compatibility kernel)

Verified in Legacy/Input.php: when Input is constructed and csrf_protection is enabled, every POST request automatically goes through Security::csrf_verify() — exactly like CI3. An invalid token produces a 403 error ("The action you have requested is not allowed.").

Inside forms, insert the token following the exact CI3 pattern:

<input type="hidden"
       name="<?= $this->security->get_csrf_token_name(); ?>"
       value="<?= $this->security->get_csrf_hash(); ?>">

Excluded URIs are matched with preg_match('#^'.$excluded.'$#i') against uri_string().

3.3 AJAX

For AJAX requests, send the token in a header and read its value as in CI3 — make sure csrf_cookie_name is readable by JS (if the token cookie needs to be non-httpOnly), or include the hash in the initial JSON response.

3.4 Modern router (kodhe/http)

⚠️ Known issue: the modern router (Route:: / kodhe/http) has no built-in CSRF middleware — CSRF verification only happens in the legacy Input pipeline. For a purely modern application:

  1. Create your own middleware (e.g. App\Middleware\CsrfMiddleware) that instantiates Kodhe\Framework\Support\Legacy\Security and then calls csrf_verify() on POST/PUT/PATCH/DELETE requests.
  2. Register its alias in app/Config/middleware.php (read by MiddlewareRegistry — keys aliases, groups, priority).
  3. Attach it to a group/route: Route::group(...)->middleware('csrf').

3.5 Migration from CI3

No changes are required: the six config keys in §3.1 are read directly by the kernel, and $this->security->get_csrf_hash() remains available. The only thing that changes is if you move to fully modern routing — see §3.4.

4. Password Hashing

Use the native PHP functions — available out of the box in PHP 8, and the package ships a compat polyfill (Support/Legacy/compat/password.php) for older environments:

$hash = password_hash($password, PASSWORD_DEFAULT);   // bcrypt, default cost
$ok   = password_verify($input, $hashFromDb);

// Transparent rehash when the bcrypt cost is raised:
if (password_needs_rehash($hashFromDb, PASSWORD_DEFAULT, ['cost' => 12])) {
    $hashFromDb = password_hash($input, PASSWORD_DEFAULT, ['cost' => 12]);
}

Migration from CI3: exactly the same — CI3 also used password_hash(). Old hash data ($2y$ prefix) can still be verified. Never store passwords with md5/sha1/do_hash(); if any remain, migrate them on the user's next login (verify the old hash → store the new one).

5. Data Encryption (kodhe/encrypt)

The Kodhe\Framework\Encrypt\Encrypt class wraps OpenSSL AES:

use Kodhe\Framework\Encrypt\Encrypt;

$encrypter = new Encrypt(['encryption_key' => $config['encryption_key']]);
// empty encryption_key -> EncryptException

$secret = $encrypter->encode('sensitive value');
$value  = $encrypter->decode($secret);

$encrypter->set_cipher('AES-256-CBC');   // set_mode('cbc') is also available
$encrypter->encode_many([...]);          // batch
$encrypter->decode_many([...]);

Key feature for migrations: migrate() detects the old ciphertext format (CI3 encrypt library) and converts it to the modern format:

if ($encrypter->is_legacy_format($stored)) {
    $stored = $encrypter->migrate($stored);  // decode old -> encode new
}

Note: distinguish encryption (secrets can be decrypted again, for stored data) from hashing (for passwords). Do not use Encrypt to store passwords.

Migration from CI3: $this->encrypt->encode()/decode() → instantiate Encrypt with the same config (encryption_key). Old ciphertext is never lost thanks to is_legacy_format() + migrate().

6. Secure Cookies & Sessions

6.1 Cookies

$config['cookie_domain']   = '';
$config['cookie_path']     = '/';
$config['cookie_secure']   = TRUE;   // only sent over HTTPS
$config['cookie_httponly'] = TRUE;   // not readable by JS

Input::set_cookie() and Security::csrf_set_cookie() honour these keys (verified). The cookie_helper.php helpers (set_cookie(), get_cookie(), delete_cookie()) are also available. If cookie_secure=TRUE but the request is not HTTPS, the CSRF cookie is deliberately not sent.

6.2 Sessions (kodhe/session package)

The default SessionConfig is already secure and configurable:

'driver'               => 'files',        // files/database/redis/memcached
'cookie_name'          => 'ci_session',
'cookie_secure'        => false,          // set to true on production HTTPS
'cookie_httponly'      => true,           // already true by default
'expiration'           => 7200,
'match_ip'             => false,          // optional IP binding
'time_to_update'       => 300,            // periodic id regeneration (seconds)
'regenerate_destroy'   => false,          // destroy old data on regeneration
'sid_length'           => 40,
'sid_bits_per_character' => 5,

ID regeneration must be performed whenever login privileges change (same advice as CI3):

session()->regenerate(true);   // regenerate + destroy old data

Migration from CI3: all old sess_* keys are recognised; the ci_sessions table is still used (see migrating-from-ci3.md §7).

7. Rate Limiting (new feature, not available in CI3)

The modern router provides Kodhe\Framework\Http\Routing\RateLimiter (CacheInterface storage) and the ThrottleRequests middleware:

use Kodhe\Framework\Http\Middleware\ApiAuth;
use Kodhe\Framework\Http\Middleware\Routing\ThrottleRequests;

// Register them as aliases in app/Config/middleware.php.
// ORDER MATTERS: 'api-auth' must come before 'throttle' so the rate-limit
// bucket is keyed per authenticated client instead of per shared IP.
Route::group('api')->middleware('api-auth', 'throttle:60,1')->group(function () {
    Route::get('users', [UserController::class, 'index']);
});

// ApiAuth needs a token validator that can be plugged into any storage:
$apiAuth = new ApiAuth(fn (string $token, $request) => $tokens->find($token)); // array|null

ThrottleRequests identity resolution (priority order): auth.id from
ApiAuth → $request->user() (web session) → PHP session ID → IP address. A
custom bucket can be forced through the third parameter: throttle:100,1,public-widgets.

RateLimiter API: tooManyAttempts(), hit(), attempts(), remaining(), availableIn(), getHeaders() (produces X-RateLimit-* headers), reset(), clear(). When the limit is exceeded, the middleware throws TooManyRequestsException (HTTP 429 + Retry-After header).

Wiring note: both classes are complete and covered by unit tests
(http/tests/Unit/Middleware/); register them manually as middleware
aliases in app/Config/middleware.php before using them — there is no
auto-wiring in the Router yet.

For simple limiting on the legacy path (e.g. login attempts), use RateLimiter directly:

$limiter = new RateLimiter($cache, ['decaySeconds' => 300]);
$key = 'login:' . $this->input->ip_address();
if ($limiter->tooManyAttempts($key, 5)) {
    // block: sleep/flash an error, reply after availableIn()
}
$limiter->hit($key);

8. Input Validation

8.1 CI3-compatible path — FormValidation

The validation/src/FormValidation.php API is a port of CI_Form_validation: set_rules(), run(), error_string(), set_value()/set_select()/set_radio()/set_checkbox(), per-URI/controller rule groups. The CI3 rules are available (required, min_length, valid_email, is_unique, etc.).

$this->load->library('form_validation');
$this->form_validation->set_rules('email', 'Email', 'trim|required|valid_email');
if ($this->form_validation->run() === false) { /* display error_string() */ }

8.2 Modern path — kodhe/validation package

Class-based validator with separate contracts (RequiredValidator, EmailValidator, IntegerValidator, NumericValidator, RegexValidator, UrlValidator, CallableValidator, CustomRuleValidator) plus Filters & MessageManager. See libraries/validation.md.

Security: is_unique in FormValidation touches the database — always combine it with allowedFields in the Model (app-components documentation §) so mass-assignment does not open an enumeration hole.

9. CAPTCHA

The captcha_helper.php helper is a CI3 port:

$this->load->helper('captcha');
$captcha = create_captcha([
    'img_path' => './captcha/',
    'img_url'  => 'https://example.com/captcha/',
    'font_url' => '',
    'img_id'   => 'imageid',
]);
// $captcha['image'], $captcha['time'], $captcha['word']

Store the captcha word in the session and verify the POSTed value against it. Make sure img_path is writable and outside sensitive areas.

10. Pre-production security checklist

  • [ ] encryption_key is set (modern format, not the old CI3 salt) — without it Encrypt throws an exception.
  • [ ] csrf_protection = TRUE + every state-changing form contains the token.
  • [ ] cookie_secure = TRUE and cookie_httponly = TRUE on production HTTPS.
  • [ ] Session: time_to_update enabled, regenerate(true) called at login.
  • [ ] display_errors off, appropriate log_threshold, log files not publicly accessible (outside the docroot or protected).
  • [ ] Uploads: validate type/size + sanitize_filename() before saving to disk.
  • [ ] Public/API endpoints get throttle (§7) — replacement for CI3 manual guards.
  • [ ] Queries always go through bindings/the Model, never concatenation of user input.
  • [ ] Full-HTTPS base_url(); outgoing redirects validated against a whitelist.
