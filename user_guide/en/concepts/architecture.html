Architecture

Kodhe Framework is the result of modularizing CodeIgniter 3 libraries into
independent Composer packages under the Kodhe\Framework\* namespace (PSR-4),
wrapped in a compatibility-layer kernel (framework/) so legacy CI3 applications
keep running.

Layers

Your application (controllers, models, config)
        │
┌───────▼───────────────────────────────┐
│ framework/  (kernel compatibility)    │  Container, dual-mode FileLoader,
│   - Service container & Setup factory │  Setup config, Console, Autoloader
│   - $CI->load->library() legacy API   │
└───────┬───────────────────────────────┘
        │ resolve via packageMap → FQCN Kodhe\Framework\<Package>\*
┌───────▼───────────────────────────────┐
│ Library packages (28 standalone)      │  validation/, pagination/, database/,
│ each with composer.json + README      │  session/, http/, email/, etc.
└───────────────────────────────────────┘

Dual-Mode Loader

FileLoader supports two loading styles:

  1. Legacy CI3: $CI->load->library('user_agent') — lowercase name, resolved through the internal packageMap to the modern FQCN (Kodhe\Framework\Agent\UserAgent), then the CI_* class alias is created automatically so old code does not change.
  2. Modern PSR-4: use Kodhe\Framework\Validation\FormValidation; directly — recommended for new code; does not depend on the loader at all.

Service Container

framework/src/Config/Setup.php registers a factory per service (session, cache,
database, etc.) that reads CI3-style configuration arrays ($config['sess_driver'],
$db['default'], …) and returns modern package instances. This is the bootstrap
path used when the application boots.

Package Principles

  • No mandatory inter-package dependencies unless truly needed (e.g. http → pagination for PaginationFactoryInterface).
  • Every package is standalone-installable: composer require kodhe/<package>.
  • The package README = source of truth for the API; user_guide/ = learning narrative.
