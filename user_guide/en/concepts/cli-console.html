CLI Console (Command Line)

Kodhe Framework ships a built-in Console component (framework/src/Console/,
namespace Kodhe\Framework\Console\) for running development and maintenance tasks from
the command line: code generation, migrations, clearing caches, jobs, and your own
custom business commands.

This is the modern console kernel (Symfony/Laravel style), different from the CI3
$this->cli that was bound to URI segments. Old CI3 applications that use a
CI_Controller for CLI still run via the compatibility kernel — see §6 for how to
migrate them.

1. Brief architecture

ClassRole
ConsoleThe CLI application manager — a singleton (Console::getInstance()), command registry, run() execution
CommandAbstract base class for all commands; subclasses must implement handle(): int
InputParses argv tokens → positional/named arguments + options (--foo=bar, -f)
OutputColoured writer: writeln/info/success/warning/error/debug/table
Commands\HelpCommandhelp [command] — general or per-command help
Commands\ListCommandlist — lists all registered commands
Commands\VersionCommandversion — the console application version
Commands\MakeCommandmake:* — boilerplate generators (see §5)

The four commands above are registered automatically when a Console is created
(registerDefaultCommands()). Custom commands are added via
addCommand() / addCommands().

2. Running the console

Create a one-time bootstrap in your project (e.g. bin/console):

#!/usr/bin/env php
<?php
require __DIR__ . '/../vendor/autoload.php';

use Kodhe\Framework\Console\Console;

$console = Console::getInstance();
$console->setName('My Application');
$console->setVersion('1.0.0');

// Register project custom commands (optional)
foreach (glob(__DIR__ . '/../app/Console/Commands/*.php') as $file) {
    $class = 'App\\Console\\Commands\\' . basename($file, '.php');
    if (class_exists($class)) {
        $console->addCommand(new $class());
    }
}

exit($console->run());   // parse argv, run the command, return the exit code
php bin/console list
php bin/console make:model User
php bin/console help migrate

run(?Input $input = null, ?Output $output = null) uses the real argv when no arguments
are given — so it can also be called from code with
$console->runCommand('make:model', ['User'], $output) for testing.

3. Writing your own command

Extend Command, declare the properties, implement handle():

namespace App\Console\Commands;

use Kodhe\Framework\Console\Command;

class SyncDataCommand extends Command
{
    protected string $name = 'sync:data';
    protected string $description = 'Synchronise data to the external system';
    protected array $usage = ['sync:data [--force] [--limit=100]'];
    protected array $arguments = ['source' => 'Name of the data source'];
    protected array $options = [
        'force' => 'Force the sync even if it already ran today',
        'limit' => 'Maximum number of rows per cycle',
    ];
    protected array $aliases = ['sd'];

    public function handle(): int
    {
        $source = $this->argument('source');          // argument by name/position
        $force  = $this->hasOption('force');          // boolean flag
        $limit  = (int) $this->option('limit', 100);  // option + default

        $this->info("Syncing source: {$source}");
        // ... business logic (use Models / service container as usual) ...
        $this->success('Done.');
        return 0;   // 0 = success; non-zero is used as the exit code
    }
}

Helper APIs available inside handle() (all from the base Command):

  • Input: argument(), option(), hasArgument(), hasOption()
  • Output: write(), writeln(), info(), success(), warning(), error(), debug(), table($headers, $rows)
  • Interactive: ask($question, $default), confirm($q, $default), choice($q, array $options, $default)

The Input parser supports positional arguments ($this->argument(0)), long options
--name=value / --flag, and combined short options -abc.

5. Code generation (make:*)

From MakeCommand (aliases: generate, g):

php bin/console make:command sync_data     # -> app/Console/Commands      (App\Console\Commands)
php bin/console make:controller Article    # -> app/Controllers           (App\Controllers)
php bin/console make:model Article         # -> app/Models                (App\Models)
php bin/console make:migration create_articles_table
php bin/console make:middleware ThrottleApi
php bin/console make:crud Article title:string body:text published:bool   # see §5b

Global generator options: --force (overwrite existing files), --path= (custom output
location). Details of each generated artefact are in
app-components.

5b. CRUD generator (make:crud)

A single command produces a complete CRUD set (modern-framework style, yet still
CI3/native flavoured): Model + full resource Controller + migration
(Loader::dbforge() modern stack) + 5 CI3-style views
(index/create/edit/show/_form) in app/Views/<resource>/.

php console make:crud Article title:string slug:string body:text published:bool
# -> app/Models/Article.php
#    app/Controllers/ArticleController.php
#    database/migrations/<ts>_create_articles_table.php
#    app/Views/articles/{index,create,edit,show,_form}.php

Full user-guide documentation (field types, route map, workflow, validation/CSRF notes):
generator-crud.

5a. Creating a new project (new) & dev server (serve)

Besides the code generators, the Console provides two project-bootstrap commands:

php console new my-app            # scaffold a complete Kodhe project skeleton
php console serve                 # dev server at http://localhost:8080
  • new (aliases create-project, new:project) creates the standard folder structure, a PSR-4 App\ composer.json, config, routes (legacy + modern), .env, and starter code. Options: --force (non-empty directory), --min (no demo code).
  • serve runs the PHP built-in server with public/index.php as the router; options --host= and --port=.

Complete guide (generated structure, config contents, quick flow):
new-project.

6. Migrating CLI usage from CI3

CI3 usually created a "CLI-only controller" (class Cli extends CI_Controller
with an is_cli() check). Conversion map:

CI3 patternKodhe Console equivalent
if (!is_cli()) show_404();not needed — Console::run() only executes from the CLI
Controller methods as "commands"one Command class per task, explicit names (sync:data)
Manual $argv[2]$this->argument(...) / $this->option(...)
echo / PHP_EOL$this->writeln()/success()/error()/table()
Exiting via show_error()return 1; from handle()
Cron calling index.php cli/synccron calls php bin/console sync:data

Migration steps:

  1. The old path keeps working: while the compatibility kernel is active, CI3-style cli/* URLs can still be executed via php index.php cli/sync as before — crons do not have to change immediately.
  2. Create a new command with make:command <name>, move the old controller method body into handle(); access services/models with the modern pattern (new App\Models\... or the container), not the $this->load superobject.
  3. Update crontab/systemd timers one by one to php bin/console <command>.
  4. Once every job has moved, delete the legacy CLI controller.

Benefits after migrating: correct exit codes for monitoring, coloured output + tables
for logs, interactive commands (confirm()) for dangerous operations, and neatly
registered commands (automatic list/help).
