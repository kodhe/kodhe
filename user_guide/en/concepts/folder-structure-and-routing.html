Folder Structure & Router (Differences from CI3)

⚠️ Migration issue to be aware of. Kodhe Framework has its own folder naming
conventions and routing system that differ from CodeIgniter 3. This page honestly
maps out the differences together with a coexistence/adapter strategy. For the
application move procedure, see Migrating from CodeIgniter 3.

1. Folder structure comparison

AreaCodeIgniter 3Kodhe (modern convention)
Application rootapplication/ (APPPATH)app/ — MakeCommand generates controllers into app/Controllers, models into app/Models, commands into app/Console/Commands (framework/src/Console/Commands/MakeCommand.php)
Folder letter caseall lowercase: controllers/, models/, core/PascalCase with a leading capital: Controllers/, Models/, Console/
Underscores in namesmany: libraries/form_validation.php, core/Security.php etc.no _ — PSR-4 classes & directories are PascalCase (FormValidation, ImageLib). Underscore-style names are only used inside the legacy kernel (framework/src/Support/Legacy/...)
Routingone file: application/config/routes.php (the $route array)two paths: CI3-style routes.php (legacy) plus modern routes APPPATH.'routes/web.php', routes/api.php, routes/console.php, and per-module routes/web.php / routes/api.php
Viewsapplication/views/Kodhe\Framework\View\Parser reads whatever path you give it — no mandatory folder; the modern convention puts them under app/Views
Controller namespaceglobal (class Welcome extends CI_Controller)App\Controllers\... (PSR-4, needs a manual autoload mapping in composer.json because the kernel does not register the App\ prefix automatically)

Important consequence: **on a case-sensitive filesystem (Linux), controllers/ ≠
Controllers/**. Old CI3 applications are still read by the kernel as-is (the loader and
LegacyRouter use APPPATH.'controllers/' with ucfirst($class)), but new
code/modules should follow the PascalCase convention so they match the modern router and
the flexible Autoloader.

2. The flexible autoloader softens part of the problem

Kodhe\Framework\Support\Autoloader (kernel) is deliberately tolerant of the CI3 style.
For every registered namespace prefix it tries the following patterns
(tryLoadClass()):

  1. The original PSR-4 path (PascalCase folder);
  2. All parts lowercase (CI3 style);
  3. Lowercase folders only;
  4. The CI3 underscore style (Product_Reviews → product_reviews.php);
  5. Controller variants with a Controller suffix (HomeController → Home.php);
  6. A case-insensitive search as a last resort (per-segment scandir).

So App\Controllers\ProductController can still load even if the old product folder is
named controllers/product.php. The limitation: this tolerance belongs to the kernel
autoloader — if you run purely per-package without kodhe/framework, Composer's strict
PSR-4 applies, so folder & class names must exactly match the namespace.

3. The Kodhe router: two engines in one class

Kodhe\Framework\Http\Routing\Router (http/src/Routing/Router.php) extends
LegacyRouter (a pure CI3 engine) and adds a modern layer. Its configuration:

'enable_modern_routing' => true,   // Route::get()/post() etc. (RouteCollection)
'enable_legacy_routing' => true,   // CI3-style $route array from config/routes.php
'prefer_modern'         => true,   // modern is matched first, falls back to legacy
'cache_routes'          => ENVIRONMENT === 'production',
'auto_detect_namespace' => true,   // URI containing '\\' → direct controller FQCN
'controller_suffix'     => '',
'default_404_controller'=> 'FileNotFound',

Request resolution flow:

  1. Modern routes (matchRequest()): the URI is matched against the RouteCollection loaded from routes/web.php|api.php|console.php in APPPATH and in every module folder (Modules::folders()). Route caching is active in production — do not forget clearCache() after changing route files.
  2. Explicit namespace in the URI: segments containing \ are resolved through parseNamespaceSegments() — action separators ::, @, or /; e.g. App\Controllers\Home@index.
  3. Legacy fallback (locate() → LegacyRouter): $route['uri'] from config/routes.php, then controller auto-detection with the ucfirst() rules:
    • module-aware: /{module}/{controller}/{method} via Modules::locations;
    • controllers/{Segment}.php, subfolders, folder-same-name patterns, down to lowercase filename attempts;
    • the default controller is searched under the names Home, Index, Main, Welcome (DEFAULT_CONTROLLER_NAMES) — different from CI3, which only knows a single default_controller from config;
    • translate_uri_dashes replaces -→_ in the first 3 segments.

The behavioural differences that surprise CI3 migrants most often:

AspectCI3Kodhe Router
Route sourcesonly config/routes.phpconfig/routes.php + routes/*.php (modern) + per-module routes; modern wins first
Target syntaxstring 'class/method'closure, 'Class@method', [Class::class, 'method'], or an FQCN with namespace
Default controller1 name from configcandidate list Home/Index/Main/Welcome
Modulesnonefirst URI segment = module name (Modules)
Cachingnoneroute collection cache in production

4. Coexistence strategy during migration

  1. Do not rename the old CI3 folders — the kernel still points at APPPATH.'controllers/'. Let the old structure live on as-is.
  2. New structures follow the Kodhe convention: create app/Controllers, app/Models (PascalCase, no _), and register their own autoload: ```json { "autoload": { "psr-4": { "App\\": "app/" } } } ``` then run composer dump-autoload -o.
  3. Bridge old URLs → new classes through modern routes, not renames: ```php // app/routes/web.php (APPPATH.'routes/web.php') use Kodhe\Framework\Http\Routing\Route; use App\Controllers\Product; Route::get('product', [Product::class, 'index']); Route::get('product/(:num)', [Product::class, 'show']); ``` With prefer_modern = true, these routes win over legacy auto-detection, so old CI3 URLs stay alive while the code moves to App\Controllers.
  4. Method/class names without underscores: write ProductReviews, not Product_reviews. The kernel's auto-tolerance covers this shortcoming in compat mode, but not in pure package mode (strict PSR-4).
  5. Be aware of name collisions: because LegacyRouter applies ucfirst() to URI segments, GET /product looks for Product.php; if the old file is named lowercase product.php, Linux case-sensitivity can make the lookup fail — the solution is an explicit modern route (point 3) or renaming the file to match the class.

5. Risk summary (known issues)

  • Capitalisation inconsistency between controllers/ (legacy runtime) and Controllers/ (the make:controller scaffold & modern MakeCommand) — two different locations can end up in one application; decide which one is authoritative per project.
  • The App\ namespace prefix is not registered automatically by the kernel; without a psr-4 entry in composer.json, controllers produced by make:controller will not be autoloaded in pure package mode.
  • The production route cache makes changes to routes/*.php invisible until the cache is cleared (Router::clearCache()); the cache file is a pure JSON document located at {cache_path}/routes.cache.json (default STORAGEPATH.'cache/', see RouteCollection::__construct()). The old legacy routes.cache.php file is read once and then migrated automatically.
  • isValidMethod() on the Router currently always returns true — validation that the method exists happens later (at execution time), so a mistyped method only surfaces as an error at a later stage than in CI3.
